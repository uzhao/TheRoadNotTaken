# agent 只写内容不写状态，且所有产出先落在生成任务目录

实测（[agy print 模式实测](../../research/agy-print-mode.md)）表明 agy 的 `--sandbox` 与 `--add-dir` 都不限制文件写入，无法把它关在数据目录里；v1 是单用户本地工具，我们选择不做 OS 级隔离，而是收窄 agent 的写权来换取可恢复性。因此：掌握状态、薄弱点、验证记录、主题会话映射只由后端写入，agent 的评分结果通过 `--json-schema` 结构化输出交给后端落盘；agent 可以写的只有内容（讲义 markdown、插图、主题提议），而且每次 agent 调用都以一次性的生成任务目录为工作目录，后端校验产出（文件存在、插图引用都在目录内、无越界路径）后才搬入数据目录正式位置，失败就丢弃任务目录。数据目录本身由 git 管理、状态文件写前做 schema 校验，作为兜底。

## Considered Options

- 单独 Unix 用户 / bubblewrap / 容器隔离 agent：能真正限制写入，但要把 agy 的登录态与 Python 绘图环境带进去，v1 不值得；记为将来可选。
- 让 agent 直接读写状态文件：最省事，但状态被写坏会让推荐整体失真且难以察觉，而讲义写坏只需重新生成。
- agent 完全不写文件、后端只收 stdout：插图必须由 agent 执行代码落盘，走不通。

## Consequences

- 推荐计算只读后端写的 `state.json`，与 agent 无直接耦合。
- 任何新增的 agent 能力（如追问中画图）都必须沿用生成任务目录，不能开例外。
- 校验失败在同一主题会话自动重试一次，再失败保留任务目录供人工查看。
