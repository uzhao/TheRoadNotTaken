## Question

网页界面应该长什么样、怎么交互？用粗糙原型（假数据、插图位置用占位框）回答：

- 知识网视图：如何呈现领域/主题与掌握状态，规模上百个主题时是否可读。
- 推荐区：下一步（学习某主题 / 做某次验证）如何呈现，如何声称掌握、暂不学。
- 学习页：讲义（历史动机、正文、例题、插图）与追问对话框的布局；流式生成时的样子。
- 验证页：作答、评分反馈、申诉、失败后的去向。

## Resolution

原型：[research/prototypes/010-ui-prototype.html](../research/prototypes/010-ui-prototype.html)（单文件、假数据，22 领域 209 主题名取自 004 调研；方案 A/B/C 三个结构不同的变体 + 合并方案 D，底部悬浮条或 `#a` `#b` `#c` `#d` 切换；线上版本 <https://claude.ai/artifact/CWvAPyyiJf2eRMoW5FjH46>）。作者比较后选定 **D = 以 A 为底的合并方案**：

1. **知识网视图**：A 的「领域侧栏 + 选中领域的主题卡片网格」为主视图；侧栏每个领域带已掌握/学习中/声称掌握的进度条。另有只读的**全图**作次级视图（顶部"看板 / 全图"切换）：每个领域一列、自上而下按前置深度分层，跨领域前置用虚线，现在可学的主题粗边；可拖动缩放、"适应宽度"；点节点跳回看板并高亮该卡。否决 B 的左右向分层图（太宽）与 C 的矩阵；使用频率预期为"想起来随便看两眼"，不按日常面板设计。
2. **推荐区**：只给**一张**推荐卡（声称掌握的验证优先于新主题），三个动作：开始/继续学习、我已掌握、暂不学；"暂不学"后立即换下一个。不展示其它候选，自选去看板点主题。排序规则留给 [推荐排序](./013-recommendation-ordering.md)。
3. **学习页**：讲义居中（衬线、约 68 字宽），顶部步骤条显示"生成正文 / 画图 xxx.svg（第 n 次尝试）/ 讲义已缓存"的流式状态，插图未就绪时占位框闪烁；**追问面板固定在右侧**，与讲义共享主题会话。否决 B 的底部抽屉与 C 的内联记录。
4. **验证页**：沿用 A 的"一页列出全部题目"，但题型从简答改为 **5 道单选题（4 选项），程序按答案键判分，答对 ≥ 4 通过**；提交后每个选项显示 agent 写的解析，错选与正确项着色；下方可**申诉一道题**（选题 + 一句理由，agent 复核后改判或作废该题、分母相应减少），每次验证一次；右侧在**提交评分后**出现"和 agent 讨论这次验证"的对话面板（验证独立会话），提交前不开放。薄弱点 = 答错题绑定的概念 + 该错选项的解析。
5. **可视化库**：否决 [技术栈](./009-tech-stack.md) 中的候选 Cytoscape.js；全图用手写 SVG 的按领域分列布局即可，不引入图库。

领域模型变更已同步：词表「验证」改为选择题定义，新增「申诉」；地图 Notes 前提同步。[prompt 与会话编排](./012-prompt-orchestration.md) 中"验证出题 / 评分 / 申诉"三项需按选择题重写：出题输出 5 题 × 4 选项 × 解析 × 绑定概念的 schema，评分不再调用 agent，申诉改为单题复核。
