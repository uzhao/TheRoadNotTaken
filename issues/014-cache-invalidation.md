## Question

已缓存的讲义何时不再可用、怎么处理？[数据目录与状态归属](./005-data-ownership.md) 已在 `meta.json` 记录主题定义哈希、薄弱点快照、模型与 effort、骨架 `version`。需要定下：

- 主题定义哈希变化（提议合并改了名称、概念或前置）时：自动重新生成、标记"可能过时"由学习者决定、还是继续使用。
- 薄弱点变化（验证失败后）时是否触发重新生成，还是只在追问与下次验证里体现。
- 模型升级或 prompt 模板改版时的处理。
- 手动"重新生成"的入口与确认方式；重新生成期间旧讲义是否仍可读。
- 插图单独重画（改脚本重跑）是否算失效的一种，走什么流程。

## Resolution

经一轮 grilling 定下（无需 ADR）：

1. **主题定义变化 → 标记过时，不自动重生成**：某主题的定义哈希与 `meta.json` 不一致时，讲义标为**过时**（已入词表）：看板卡片与讲义页顶部显示"主题定义已在骨架 v{N} 更改（改了：概念提纲/前置/名称）"及"重新生成"按钮；不阻止阅读，不改掌握状态。
2. **验证失败 → 两个按钮**："重读现有讲义"（默认、即时）与"针对薄弱点重新生成"（新主题会话、1–2 分钟）；薄弱点无论如何进入追问与下次出题的 prompt（012）。010 原型中的"带着薄弱点重读讲义"按此拆成两个。
3. **模板与模型改版不算失效**：`meta.json` 只记录，不标记、不提示；想换就手动重生成。
4. **手动重生成**：讲义页常驻"重新生成"按钮；页内确认条说明旧讲义进入 git 历史、追问记录保留、将开新主题会话；生成期间学习页显示流式的新讲义并可"查看旧版"，直到新讲义通过校验后整目录替换（005）；失败则旧讲义原样保留并提示。
5. **单张插图重画不算失效**：每张插图旁"重画这张图"（可附一句要求），在主题会话里让 agy 修改 `figures/<名>.py` 并重跑，经生成任务目录校验后只替换该图与脚本；`lecture.md` 与重生成次数不动。
6. 骨架 `version` 变化但该主题定义未变 → 无影响；退役主题的讲义按 008 删除；已掌握主题的讲义永不自动重生成（供回看）。
