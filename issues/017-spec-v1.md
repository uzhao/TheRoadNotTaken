## Problem Statement

一位有高中数学基础的自学者想系统补上大学数学，但没有固定目标、没有课表，也不想自己规划先学什么。现成的教材和课程按作者的顺序走，不知道他已经会了什么、哪里薄弱；通用的 AI 聊天每次从零开始，讲完就散，既不记得他学到哪、也没法告诉他下一步。他想要的是一个开着就能告诉他"现在学这个"的本地工具：讲义由 agent 现写、带历史动机和插图，读的时候能追问，读完做几道题确认自己真会了，然后系统自动把下一步排出来。他不会天天用，想起来看一两篇，所以每次回来都不该需要重新想"我在哪"。

## Solution

一个单用户、本地运行的网页应用。它维护一张覆盖大学数学 22 个领域、约 209 个主题的**知识网**，用**骨架**文件定义领域、主题与前置关系；用一份状态文件记录每个主题的掌握状态与薄弱点。打开应用，顶部只有一张**推荐**卡：要么学某个主题，要么验证某个声称掌握的主题。进入主题后，agent（`agy` print 模式）现写一份**讲义**，以历史动机开篇，正文按概念分节，含例题与 matplotlib 插图，正文流式出现，右侧可**追问**。学完做**验证**：5 道单选题，程序判分，至多错一题通过，通过即**已掌握**，后继主题随之解锁；不通过则记录**薄弱点**，回到学习中。学习中发现骨架缺漏，agent 会提**主题提议**，下次启动时由学习者逐条确认合并。所有数据都是人可读的文本文件，放在一个由 git 管理的**数据目录**里。

## User Stories

### 知识网与骨架

1. 作为学习者，我想在左侧看到按主干与分支分组的全部领域及各自的掌握进度，以便一眼知道自己学到哪了。
2. 作为学习者，我想点某个领域看到它的全部主题卡片（名称、概念提纲、状态、前置），以便自己挑着看。
3. 作为学习者，我想切到一张只读的全图，每个领域一列、自上而下按前置深度排列，以便偶尔看一眼整体结构和"路"长什么样。
4. 作为学习者，我想在全图上点一个主题就跳回看板对应的卡片，以便从全局视角直接进入某个主题。
5. 作为学习者，我想看到前置未掌握的主题被标为不可学并列出缺哪些前置，以便明白为什么现在还不能学它。
6. 作为学习者，我想高中数学不出现在知识网里而直接视为已掌握，以便不被我早已会的东西打扰。
7. 作为作者，我想骨架是一份可手改的 YAML，以便在编辑器里直接修正领域、主题与前置。
8. 作为作者，我想应用启动时校验骨架（id 唯一、前置存在、无环、主干不依赖分支、每个主题从初始前沿可达、概念 3–5 个），不合法就拒绝启动并指出位置，以便手改错了能立刻知道。
9. 作为作者，我想仓库里带一份审定的种子骨架、首次启动时复制到数据目录，以便新装机器开箱可用而数据目录仍是权威。
10. 作为作者，我想有一个独立的骨架校验脚本能对一份 YAML 片段输出每领域的前置清单，以便在生成与审核 209 个主题时逐领域检查。

### 推荐

11. 作为学习者，我想打开应用只看到一张推荐卡，以便不用自己想该看哪个。
12. 作为学习者，我想推荐卡写明推荐的理由（如"你声称掌握，先验证""上次没学完""接着线性代数 I 往下""它解锁 4 个主题"），以便判断规则是否合理。
13. 作为学习者，我想声称掌握的主题的验证永远排在新主题之前，以便先把挡路的事做掉。
14. 作为学习者，我想没学完的主题优先于没开始的主题，以便接着上次的来。
15. 作为学习者，我想主干主题优先于分支主题，并且推荐尽量与我最近学的主题同领域，以便少切换上下文。
16. 作为学习者，我想在推荐卡上直接"开始学习""我已掌握""暂不学"，以便一步到位。
17. 作为学习者，我想"暂不学"后立刻换下一个推荐，暂不学的主题在没有其它可学主题时再回来，并且随时能在看板上手动恢复，以便搁置而不是丢失。
18. 作为学习者，我想分支领域默认不参与推荐，每个分支领域有"纳入推荐"开关，以便自己决定什么时候碰应用方向。
19. 作为学习者，我想当没有任何可推荐主题时看到明确提示（开启分支或去看板自选），以便不困惑。

### 学习与讲义

20. 作为学习者，我想点"开始学习"后讲义正文逐字流式出现，以便不用对着空白页等一分钟。
21. 作为学习者，我想讲义以历史动机开篇，然后每个概念一节，再是两道有完整解答的例题、常见误区与小结，以便每份讲义结构一致。
22. 作为学习者，我想讲义里有 agent 现画的插图（函数图像、几何示意等），每张有一句中文图注，以便直观理解。
23. 作为学习者，我想在插图还没画好时看到占位框和"正在画图（第 n 次尝试）"的状态，以便知道系统没卡死。
24. 作为学习者，我想讲义中的公式正确渲染，不支持的命令显示原始 TeX 而不是整段失败，以便阅读不被打断。
25. 作为学习者，我想讲义生成一次后缓存，再次打开立即可读，以便回看不花时间。
26. 作为学习者，我想讲义顶部显示该主题当前的薄弱点，重新生成时讲义会重点覆盖它们，以便针对性补课。
27. 作为学习者，我想讲义页有"重新生成"按钮，点击后页内确认（旧版进 git 历史、追问保留、开新会话）再开始，生成期间能看旧版，失败则旧版原样保留，以便安心重写。
28. 作为学习者，我想每张插图旁有"重画这张图"并可附一句要求，只替换这一张图及其脚本，以便微调而不重写全文。
29. 作为学习者，我想主题定义被提议合并改过之后，讲义被标为"过时"并说明改了什么，但仍可读、不自动重写，以便自己决定要不要重生成。
30. 作为学习者，我想学完后点"我学完了，去验证"，或点"稍后再学"回到知识网且该主题保持学习中，以便随时中断。

### 追问

31. 作为学习者，我想在讲义右侧的固定面板里追问，agent 知道我刚读到哪一节，以便就地提问。
32. 作为学习者，我想追问续接讲义的同一个会话，不用重复背景，以便对话自然。
33. 作为学习者，我想追问回答默认简短（约 300 字），需要时可以要求展开，以便不被长篇淹没。
34. 作为学习者，我想追问时 agent 也能画图（最多两张），以便解释几何问题。
35. 作为学习者，我想追问记录被保存并在"历史"页签里回看，以便下次接着看。

### 验证

36. 作为学习者，我想验证是 5 道单选题一页列出，以便快速作答。
37. 作为学习者，我想题目覆盖该主题的每个概念，有薄弱点时至少两题针对薄弱点，且不与最近两次验证重复，以便验证真的在测我不会的地方。
38. 作为学习者，我想选项顺序被打乱，以便不能靠"正确项总在 D"作弊。
39. 作为学习者，我想提交后立即看到判分（程序按答案键，不等 agent），每个选项显示解析，错选与正确项着色，以便马上知道错在哪。
40. 作为学习者，我想至多错一题即通过，通过后主题标为已掌握、薄弱点清空、后继主题解锁，以便推进。
41. 作为学习者，我想未通过时主题回到学习中，薄弱点记为"概念：错选项解析"，并看到"重读现有讲义"与"针对薄弱点重新生成"两个选择，以便决定怎么补。
42. 作为学习者，我想对一道我认为答案键有误或题意有歧义的题申诉一次，写一句理由，由 agent 复核后维持、改判或作废该题，作废后按新分母重新判定，以便纠正出题错误。
43. 作为学习者，我想提交评分后右侧出现与 agent 讨论这次验证的面板，提交前不出现，以便讨论错题但不开卷。
44. 作为学习者，我想已掌握的主题能"再验一次"，通过只追加记录，未通过则退回学习中但不影响后继主题，以便诚实复核。
45. 作为学习者，我想在"历史"页签看到每次验证的日期、几对几、是否通过、申诉结果与每题作答，以便回看。
46. 作为学习者，我想点"我已掌握"后主题变为声称掌握，推荐随即变成"开始验证"，并且可以点"其实没学过"撤回，以便声称的代价只是做一次题。

### 主题提议与合并

47. 作为学习者，我想 agent 在写讲义或回答追问时发现骨架缺前置、主题过大或缺概念时自动记一条提议（每次最多三条），以便骨架随学习自我修正。
48. 作为学习者，我想自己也能通过表单提一条提议（类型、相关主题、描述），以便记录我的想法。
49. 作为学习者，我想有待处理提议时应用启动先进入"待处理提议"页，逐条处理或点"稍后"跳过后再进主界面，以便合并发生在骨架被使用之前。
50. 作为学习者，我想点"起草"让 agent 把提议变成具体的骨架改动并看到前后差异，可编辑后"应用"或"拒绝"，以便不用手写 YAML。
51. 作为学习者，我想应用改动时自动跑骨架校验、通过才写入并提交 git、骨架版本号加一，不通过显示错误而提议保持待处理，以便骨架永远合法。
52. 作为学习者，我想拆分主题时旧主题退役、新主题新建，旧主题若已掌握则新主题置为声称掌握，以便已有进度不被抹掉也不被高估。
53. 作为学习者，我想重命名只改名字、改前置不改任何掌握状态、移除主题时依赖它的主题改指向其前置，以便合并的影响可预期。
54. 作为学习者，我想被拒的提议不再出现，以便列表只剩待办。

### 数据与安全

55. 作为作者，我想全部数据放在一个可配置的根目录里、全是人可读的文本文件、没有数据库，以便随时手改与备份。
56. 作为作者，我想数据目录是一个本地 git 仓库，每次状态写入或讲义搬入都自动提交、提交信息人可读，以便用 git 恢复与回看"最近做了什么"。
57. 作为作者，我想 agent 只能写讲义、插图与提议，掌握状态、薄弱点、验证记录与会话映射只有后端写，以便 agent 写坏了最多重写一份讲义。
58. 作为作者，我想每次 agent 调用都在一次性的生成任务目录里进行，产出经校验后才搬入正式位置，失败的目录保留供排查，以便缓存里永远只有完整内容。
59. 作为作者，我想状态文件写前做 schema 校验、用临时文件原子替换，以便不会出现半个 JSON。
60. 作为作者，我想主题 id 是稳定 slug、有状态或讲义后永不改、退役后永不复用，以便目录与记录永不错位。
61. 作为作者，我想前端只用 `<img>` 显示插图、不内联 SVG、不执行任何 agent 生成的代码、原始 HTML 当文本，以便没有浏览器内代码执行风险。
62. 作为作者，我想后端不用 `--dangerously-skip-permissions`，而是依赖 agy 全局 settings 中四条最小 allow 规则，启动时校验并在缺失时提示可一键写入，以便 agent 能画图但拿不到网络工具。

### 故障

63. 作为学习者，我想可重试的 agent 错误自动重试一次，不可重试的直接报错并显示简短原因与错误 id，以便知道发生了什么。
64. 作为学习者，我想生成超时时已流出的部分正文留在页面上并标明未缓存，可以重试，以便不白等。
65. 作为学习者，我想任何失败都不改我的掌握状态、不消耗申诉次数、不留下半份讲义，以便失败可以无代价重来。
66. 作为学习者，我想 agent 不可用（未登录、断网、配额耗尽）时顶栏有横幅说明原因与配额重置时间，缓存讲义照常可读，生成类按钮置灰并可"重试连接"，以便离线也能复习。
67. 作为学习者，我想错误面板里"换个模型重试"能一次性换模型，但系统从不自动换模型，以便风格一致又有退路。
68. 作为学习者，我想同时最多两个生成任务在跑，多的排队显示位次，排队与运行中的任务都能取消且不改状态，以便控制资源。
69. 作为学习者，我想后端重启后看到"上次生成被中断"并能重试，以便不丢上下文。
70. 作为作者，我想失败的任务目录与 agent 原始事件日志保留 7 天、最多 20 个，以便排查又不堆积。

### 运行与开发

71. 作为作者，我想一条命令启动整个应用（后端托管前端静态文件与 API），以便日常使用零配置。
72. 作为作者，我想开发时前端热更新并代理到后端，以便迭代界面。
73. 作为作者，我想 prompt 模板是带版本号的文件，讲义元数据记录生成时的模板版本、模型与 effort，以便回溯一份讲义是怎么来的。

## Implementation Decisions

### 架构与技术栈（[ADR-0003](../docs/adr/0003-tech-stack.md)、[技术栈](./009-tech-stack.md)）

- 后端 Python + FastAPI + uvicorn，依赖管理 uv，pydantic 校验状态与 agent 结构化输出，ruamel.yaml 读写骨架以保留注释与顺序，git 操作直接调命令行。
- 前端 React + TypeScript + Vite 单页应用，pnpm；`react-markdown` + `remark-math` + `rehype-katex`，不启用 `rehype-raw`；KaTeX 及字体随前端打包离线，`throwOnError: false`；流式时对累计文本约每 100 ms 节流重渲染。
- 仓库为 monorepo：后端包、前端项目、种子骨架三个顶层目录。生产形态为一条命令启动，后端同时托管前端构建产物与 API；开发时 Vite dev server 代理后端。数据目录来自命令行参数或环境变量，有缺省位置。
- 长任务（讲义、追问、验证出题、申诉、起草、重画插图）由后端创建任务返回 id，前端用 `EventSource` 订阅任务事件流；其余为 JSON REST。不用 WebSocket。
- 知识网全图用手写 SVG 的按领域分列布局（每领域一列、按前置深度排行、跨领域前置虚线、可拖动缩放、"适应宽度"），不引入图可视化库。

### agent 调用（[ADR-0001](../docs/adr/0001-agent-writes-content-not-state.md)、[agy print 模式实测](./002-agy-print-mode.md)、[agy 权限规则配置实测](./011-agy-permission-rules.md)）

- 每个生成任务启一个 `agy` 子进程：`--output-format stream-json --disable-slash-commands`，续接时加 `--conversation <id>`，prompt 以 `--print='…'` 传入（`-p` 的下一个词即 prompt，参数必须放在它前面）；cwd 为该任务的生成任务目录。不做常驻进程。
- 后端逐行解析 NDJSON：`init` 事件（首行）给出会话 id，立即持久化；`step_update` 中 `agent_response` 步的 `text_delta` 转为正文增量事件，`tool` 步的 ACTIVE/DONE 转为"正在画图 / 执行命令"状态事件；`result` 给出全文与用量；非 JSON 行记日志忽略。
- 退出码：0 表示成功、权限拒绝或 `--print-timeout` 到期；3 表示模型/配额错误，stderr 有 `AGY_ERROR:` JSON（含 `retryable`、`short_error`、`error_id`）。后端不依赖 `--print-timeout`，自备硬超时并杀进程组：讲义 10 分钟、追问 5 分钟、验证出题与申诉 3 分钟。并发上限 2，其余排队；任务状态在内存。
- 权限：不用 `--dangerously-skip-permissions`。要求 agy 全局 settings（`~/.gemini/antigravity-cli/settings.json`）的 `permissions.allow` 含 `command(python3)`、`command(python3 *)`、`command(mkdir)`、`write_file(*)`；启动时读取校验，缺失则横幅提示并提供页内确认的"写入规则"（追加、不覆盖其它键）。不写 deny。
- `--json-schema` 的结果取 `structured_output` 字段并本地再校验；其中会混入 `toolAction` / `toolSummary` 等 schema 外字段，解析时忽略未知键；`status` 为 `SUCCESS` 但无 `structured_output` 视为失败。
- 模型：所有调用用同一个可配置默认模型（当前为 agy 默认 Gemini 4 Argon）；effort 两档：讲义与出题 `high`，追问、申诉、验证后对话、起草 `medium`；一个会话内不换模型。

### 数据目录（[数据目录与状态归属](./005-data-ownership.md)、[提议清单合并流程](./008-proposal-merge.md)）

- 单一根目录，全部文本文件，初始化为本地 git 仓库；后端每次写状态或搬入产出后自动提交，提交信息人可读；生成任务目录被 git 忽略。布局：

  ```
  skeleton.yaml  state.json  conversations.json  proposals.yaml
  lectures/<主题id>/{lecture.md, figures/, meta.json, followups.jsonl}
  jobs/<任务id>/   .git/
  ```

- 写权分界：状态（掌握状态、薄弱点、暂不学、声称掌握、验证记录、会话映射）只有后端写；内容（讲义、插图、提议）由 agent 产出但先落生成任务目录，经校验后由后端搬入。`proposals.yaml` 实际只有后端一个写者。推荐计算只读后端写的状态。
- 搬运校验：讲义回复非空且以一级标题开头；每个 `![]()` 指向任务目录内 `figures/` 的 svg/png，无绝对路径与 `..`；`figures/` 内放行同名 `.py` 脚本；SVG 可被 XML 解析且根元素为 `<svg>`，PNG 文件头正确；每份讲义插图 0–4 张、追问单次 ≤ 2 张、验证后对话 ≤ 1 张、每张 ≤ 500 KB；多余文件丢弃。校验失败在同一会话自动重试一次并告知错误（允许"修好图，或删掉引用并改写该段"），再失败整个任务失败、目录保留。
- 状态文件单文件、键为主题 id、临时文件 + 原子改名、写前 schema 校验。每项（来自工单草案）：

  ```json
  "<主题id>": {
    "status": "unlearned | learning | deferred | claimed | mastered",
    "weak_points": ["<概念>：<错选项的解析>"],
    "verifications": [{"at", "conversation_id",
      "questions": [{"concept","stem","options","answer","picked","explanations"}],
      "right", "denom", "passed",
      "appeal": null | {"question","reason","verdict","explanation","at"}}],
    "updated_at": "..."
  }
  ```

  退役主题的条目移入 `archived` 段。高中数学不入此文件。
- 会话映射：每主题一个当前主题会话 id，在 `init` 事件到达时写入；讲义重新生成即开新会话覆盖旧 id；追问始终续接当前会话。验证每次新开独立会话，id 记在验证记录里，不进映射文件。
- `meta.json`：生成时间、模型与 effort、prompt 模板版本、主题定义哈希（名称 + 概念提纲 + 前置）、薄弱点快照、重生成次数、生成任务 id。
- `followups.jsonl`：每轮问答一条（时间、问、答、任务 id、`kind: lecture | verification`、验证序号）；重新生成讲义时保留。追问产生的插图搬入同一 `figures/`，文件名加任务 id 前缀。
- `proposals.yaml`：追加式条目 `id`、`created_at`、`source`（`agent | learner`）、`topic`（可空）、`kind`（`new-topic | change-prerequisite | rename | split | remove | other`）、`text`、`status`（`pending | merged | rejected`）。去重：同主题、同类型、文本完全相同的待处理条目不重复追加。
- 失败任务目录保留 7 天、最多 20 个，启动时清理；成功的搬运后立即删除；每任务的原始 NDJSON 落在目录内的 `agy.ndjson`。后端日志按天滚动保留 14 天。

### 骨架（[第一版骨架](./007-first-skeleton.md)、[参考课程体系与历史素材调研](./004-curriculum-references.md)）

- 覆盖 14 个主干领域（137 主题）与 8 个分支领域（72 主题），约 209 个主题；主题 = 大学课堂 1–2 讲、3–5 个概念；检验标准是"1500–3000 字、≤ 4 张插图的讲义能讲完，5 道单选题能覆盖"。
- YAML 两层（来自工单草案）：

  ```yaml
  version: 1
  fields:
    - {id: c02, name: 单变量微积分与数学分析基础, kind: core, order: 2}
  topics:
    - id: c02-derivative-definition      # 稳定 slug，永不改
      name: 导数、微分与求导法则
      field: c02
      concepts: [切线与瞬时变化率, 链式法则, 反函数与隐函数求导, 高阶导数与 Leibniz 公式]
      prerequisites: [c02-function-limit-continuity]   # 直接前置
      history: "Kline Ch.17"
      references: []
  retired: []   # {id, retired_at, successors, proposal}
  ```

- 前置为主题级直接边（不记传递边），通常 1–3 条；主干主题的前置只能是主干主题；除初始前沿外每个主题至少一条入边，所有主题从初始前沿可达；主题在领域内的顺序即列表顺序，无语义；高中数学不建节点。
- 启动时读入并校验（id 唯一、前置存在、无环、领域已定义、方向约束、入边与可达性、概念 3–5 个、新 id 不与现役及退役 id 重复），失败拒绝启动并指出位置；运行期不热加载，手改 = 改文件后重启。
- 种子骨架随仓库分发，首次启动复制到数据目录，此后数据目录副本为权威。
- 生成流程（实施的第一项任务）：以调研报告为输入，agent 用 `--json-schema` 按领域逐个产出主题 id、概念、领域内前置，再产出跨领域前置；校验脚本检查并输出每领域 markdown 前置清单；作者按领域逐个审核；合并为一份种子骨架。

### 推荐（[推荐排序](./013-recommendation-ordering.md)）

- 候选 = 状态为 `unlearned` 或 `learning` 且全部直接前置均 `mastered` 的主题，加上所有 `claimed` 主题；`deferred` 不在候选中。
- 确定性字典序取唯一推荐：待验证 > 学习中 > 主干 > 与最近一次状态变化（按 `updated_at`）的主题同领域 > 直接后继数多 > 主题 id 升序。每次状态变化重算，无随机。
- 分支领域按领域开关、默认关闭、开启后仍排在主干之后；`deferred` 主题在候选耗尽时回归并标"之前暂不学"，看板上可手动恢复；候选为空且无 `deferred` 时提示。
- 推荐卡显示命中规则生成的一句理由。

### 讲义、追问与插图（[prompt 与会话编排](./012-prompt-orchestration.md)、[插图方案选型](./006-figure-choice.md)、[ADR-0002](../docs/adr/0002-static-figures-no-frontend-code-execution.md)、[讲义缓存失效](./014-cache-invalidation.md)）

- 讲义 prompt 由后端拼装：学习者画像一句话、主题名与领域、概念提纲、直接前置主题名（已掌握、可直接引用）、当前薄弱点、历史动机索引、插图契约、提议规则、输出格式。prompt 模板为带版本号的文件。
- 讲义是 agent 的**最终回复**（markdown，无前言后记，不加 `--json-schema`），后端将其写为 `lecture.md`；插图与提议由 agent 写到任务目录。结构只靠 prompt 约束：`# 主题名` → `## 历史动机`（200–400 字）→ 每个概念一节 → `## 例题`（2 道）→ `## 常见误区`（可选）→ `## 小结`；全文 1500–3000 字。
- 插图：agent 执行 Python + matplotlib 产出 SVG（例外 PNG），脚本并排保存；后端在每个任务目录放统一的 `matplotlibrc`（Noto Sans CJK、`svg.fonttype: none`、固定画布与 dpi、mathtext、不依赖 TeX，启动时检查字体缺则警告）；插图契约：语义化英文文件名、一句独立成立的中文图注、标签优先数学记号、坐标轴有标签、白底浅色；不做视觉自检；前端 `<img>` 显示后端静态路由的文件（路径包含检查）；v1 无交互插图。
- 追问：续接主题会话，不重发讲义；消息包装为学习者问题 + 当前所在节标题 + 薄弱点（仅当有变化）+ 约束（默认 ≤ 300 字、插图 ≤ 2 张、可写提议）。
- 过时：主题定义哈希与 `meta.json` 不一致时讲义标"过时"（说明改了什么）并给"重新生成"按钮，不自动重生成、不改状态；模板与模型改版不算过时。手动重生成有页内确认、生成期间可看旧版、成功后整目录替换（`followups.jsonl` 保留）、失败保留旧版。单张插图重画在主题会话里改脚本重跑、只替换该图与脚本、不计重生成次数。

### 验证（[主界面原型](./010-ui-prototype.md)、[prompt 与会话编排](./012-prompt-orchestration.md)）

- 出题：每次验证新开独立会话；输入主题定义与概念提纲、薄弱点、最近两次验证的题干；输出 `--json-schema`：恰好 5 题，每题 `concept`（属于提纲）、`stem`、`options`（4 个互不相同）、`answer`（0–3）、`explanations`（4 条）；覆盖规则：每个概念至少 1 题，有薄弱点则至少 2 题针对之，干扰项为常见误解，禁止"以上都对/都不对"。后端校验结构并打乱选项顺序。
- 判分：程序按答案键，不调用 agent；通过 = 至多错一题（5 题 ≥ 4；作废一题后 4 题 ≥ 3）。通过 → `mastered`、薄弱点清空；未通过 → `learning`、薄弱点 = 答错题的"概念：错选项解析"。
- 申诉：每次验证一次；续接验证会话，输入题号、所选项、理由；输出 `{verdict: uphold | overturn | void, explanation}`；`overturn` 记为答对，`void` 移出分母后重新判定。申诉失败不消耗次数。
- 验证后对话：提交评分后才开放，续接验证会话，首条消息附作答与判分结果，之后只传问题；记入 `followups.jsonl`（`kind: verification`）。
- 已掌握主题可"再验一次"：通过追加记录；未通过退回 `learning` 并记薄弱点，后继主题不级联。

### 提议合并（[提议清单合并流程](./008-proposal-merge.md)）

- agent 的提议写在任务目录的 `proposals.yaml`（≤ 3 条/次，仅在发现缺前置、主题过大、缺概念时），后端校验后追加，`source: agent`；学习者走表单，`source: learner`。
- 启动门槛：有 `pending` 提议时先进入"待处理提议"页，逐条处理或"稍后"跳过后再加载骨架进主界面；不做运行期合并。
- 处理：点"起草"让 agent 在独立会话用 `--json-schema` 产出具体骨架改动，界面显示前后差异，可编辑后"应用"或"拒绝"；应用时跑骨架校验，通过才写入、`version` 加一、git 提交；不通过显示错误、提议保持 `pending`。`other` 类只能人工处理。
- 影响：`new-topic` 新主题 `unlearned`；`change-prerequisite` 不改状态；`rename` 只改名；`split` 旧 id 退役、旧主题 `mastered` 则新主题全部 `claimed`、其它为 `unlearned`、旧讲义目录删除、旧记录归档；`remove` 退役并把依赖者改指向其前置。被拒提议保留不再显示、不回灌 prompt。

### 界面（[主界面原型](./010-ui-prototype.md)、[学习历史与复习](./016-learning-history-review.md)）

- 顶栏：品牌、"知识网 / 学习 / 验证"导航、已掌握计数；agent 不可用或权限缺失时的全局横幅。
- 知识网页：左侧领域侧栏（主干/分支分组、进度条、分支的"纳入推荐"开关）；主区顶部一张推荐卡 + "看板 / 全图"切换；看板为选中领域的主题卡片网格（状态标签、概念提纲、动作或缺失前置说明、过时与生成失败标记）；全图如上。
- 学习页：讲义居中（衬线、约 68 字宽），顶部步骤条显示流式状态，插图占位；右侧固定面板分"追问 / 历史"页签；底部"我学完了，去验证""稍后再学"；顶部"重新生成"。
- 验证页：5 题一页列出，提交按钮显示已作答数；结果页显示通过/未通过、几对几、薄弱点、"重读现有讲义 / 针对薄弱点重新生成"或"回到知识网"、申诉区、每题解析；右侧评分后出现讨论面板。
- 待处理提议页：逐条卡片（来源、类型、主题、描述），动作"起草 / 应用 / 拒绝 / 稍后"，差异对照。
- 错误面板：`short_error`、`error_id`、"复制诊断信息"、"重试"、"换个模型重试"；排队位次与取消；"上次生成被中断"提示。

### 故障处理（[故障处理](./015-failure-handling.md)）

- 自动重试矩阵：`retryable` 的 `AGY_ERROR` 10 秒后同模型重试一次；不可重试的直接报错；硬超时不重试、保留部分正文且不缓存；无 `structured_output` 同会话补一次；`denied_actions` 视为配置错误并指向权限规则；搬运校验失败同会话重试一次。
- 失败不写任何状态：讲义失败主题仍 `learning`、卡片标"生成失败"；追问失败不记录；出题失败不写验证记录；申诉失败不消耗次数；起草失败提议保持 `pending`。
- agent 不可用：启动不做健康检查；首次失败即全局横幅，缓存可读，生成类操作置灰，"重试连接"做一次最小调用。
- 后端重启：未完成任务视为失败并清理，刷新后提示可重试。

## Testing Decisions

- **好测试的标准**：只断言外部可观察行为——HTTP 响应、SSE 事件序列、数据目录里的文件内容、git 提交——不断言内部函数与模块结构。每个测试从一个空的临时数据目录和一份小骨架开始，不依赖其它测试留下的状态。
- **唯一主缝：后端 HTTP API + 假 agy + 临时数据目录。** 测试启动真实的 FastAPI 应用，数据目录指向临时目录，`PATH` 前置一个假 `agy` 可执行文件。假 agy 按测试提供的脚本回放 stream-json 事件（`init`、`text_delta`、工具步、`result`），按脚本在 cwd 写插图与提议文件，并能模拟 002/015 列出的全部故障形态：exit 3 + `AGY_ERROR`（可重试 / 不可重试）、长时间不退出（触发硬超时）、`SUCCESS` 但无 `structured_output`、`denied_actions`、写出越界路径或超大文件、输出非 JSON 行。它同时记录收到的命令行参数与 prompt，供测试断言会话 id、effort、`--disable-slash-commands` 等调用约定。
- **通过主缝覆盖的行为**：推荐排序与前沿计算（构造状态后请求推荐）；讲义生成全流程（SSE 顺序、`lecture.md` 落盘、`meta.json` 字段、会话映射在 `init` 时写入、git 提交）；搬运校验的每条规则与一次重试；追问续接与 `followups.jsonl`；验证出题校验与选项打乱、判分、通过/未通过的状态与薄弱点、申诉三种裁决、再验一次；提议追加、去重、启动门槛、起草与应用（含校验失败不写入、版本号递增、各类提议对状态与讲义的影响、退役表）；过时标记与重新生成、单图重画；故障矩阵中每一格对应的状态不变性；并发上限、排队、取消、重启清理；权限规则缺失的横幅与写入。
- **骨架校验脚本**按命令行方式单独测试（合法骨架通过；每种违规各一个最小用例并断言错误定位），因为它要在生成骨架阶段独立运行。
- **前端**：少量 Playwright 端到端用例跑在真实后端 + 假 agy 上，覆盖"推荐 → 开始学习 → 流式讲义出现 → 去验证 → 通过 → 推荐变化"与"验证未通过 → 两个按钮 → 重读讲义"两条主路径；不做组件级单元测试。
- **不进自动化测试**：真实 agy 调用（保留 002/011 的手动脚本作为冒烟）；matplotlib 真实出图质量。
- **先例**：仓库尚无代码，本规格的测试是第一批；后续实施工单沿用上述缝，不新增缝。

## Out of Scope

- 多用户、账号、部署；原生 LLM API 调用；PDF 资料导入（骨架上仅保留 `references` 占位）。
- 按目标倒推路径或按历史顺序学习的"路线"。
- 交互式插图（JSXGraph 等）、插图视觉自检、Mermaid、动画；深色模式下的插图配色。
- 常驻 agy 进程（`--input-format stream-json` 的输入格式未打通）；自动切换模型；OS 级隔离 agent（单独用户 / 容器）。
- 间隔重复算法与复习排程、学习时长与打卡统计、笔记与导出、全局时间线或事件日志界面。
- 运行期合并提议、骨架热加载、被拒提议回灌 prompt、提议的语义去重。
- 验证作答过程中与 agent 交流；简答题。
