## What to build

学习者首次启动时，应用在数据目录里复制种子骨架、初始化 git 仓库、建立空的状态文件、会话映射与提议清单，并提交首个 commit；此后每次启动读入并校验骨架，不合法则拒绝启动并指出位置。知识网页显示：左侧按主干/分支分组的领域侧栏（名称、已掌握/总数、三色进度条），主区为选中领域的主题卡片网格（名称、概念提纲、状态标签、缺失的前置名），顶栏显示已掌握计数。用样例骨架即可演示。

## Acceptance criteria

- [ ] 空目录启动后存在骨架副本、`state.json`（空对象）、`conversations.json`、`proposals.yaml`、`.git` 且 `jobs/` 被忽略
- [ ] 已有数据目录再次启动不覆盖任何文件
- [ ] 骨架校验失败时进程以非零退出并打印定位
- [ ] API 提供领域、主题与状态的只读视图；前端侧栏与看板按规格布局渲染，锁定主题标出缺失前置
- [ ] 状态文件读取经 pydantic 校验，非法内容拒绝启动并提示
