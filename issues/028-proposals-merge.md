## What to build

讲义与追问任务目录里的提议经校验追加到提议清单（来源 agent、每次最多三条、精确去重），学习者也可用表单提交。有待处理提议时启动先进入「待处理提议」页，逐条「起草 / 应用 / 拒绝 / 稍后」；起草由 agent 在独立会话产出具体骨架改动并显示前后差异，可编辑；应用时跑骨架校验，通过才写入、版本号加一、git 提交，并按类型处理状态与讲义：新增主题为未学、改前置不改状态、重命名只改名、拆分退役旧 id 且已掌握→声称掌握、移除退役并改接依赖者；`other` 类无起草。

## Acceptance criteria

- [ ] 任务目录中的提议文件格式错误或超过三条时整体丢弃并记日志，不影响讲义搬入
- [ ] 启动门槛：有 pending 时首页为提议页，全部处理或「稍后」后进入主界面；无 pending 直接进主界面
- [ ] 起草任务输出经 schema 校验后以差异形式展示；应用失败时骨架文件不变、提议仍为 pending
- [ ] 五种提议类型各有用例断言骨架、退役表、状态文件与讲义目录的变化
- [ ] 被拒提议不再显示但仍在文件中
